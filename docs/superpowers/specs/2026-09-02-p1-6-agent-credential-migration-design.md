# P1-6 Agent 凭证迁移与 HMAC 强制上线设计

## 背景

当前系统已经支持为新 Agent 生成 API Key 与签名密钥，也支持兼容历史的无签名 Agent 凭证。生产环境不能直接把 `AGENT_SIGNATURE_REQUIRED` 切换为 `true`，否则仍使用历史 SDK 的 Agent 会在没有迁移提示的情况下全部失败。

本阶段的目标是建立一个可观测、可回滚、不可泄露明文密钥的迁移闭环：运营人员能够识别租户内仍需迁移的 Agent，逐个轮换凭证，确认所有活跃 Agent 已具备签名密钥后，再通过启动前检查开启 HMAC 强制模式。

## 目标与非目标

### 目标

- 提供租户范围的凭证迁移摘要和历史 Agent 列表。
- 提供全局启动前检查，阻止存在历史活跃凭证时误开启 HMAC 强制模式。
- 复用已有的 Agent 凭证轮换接口完成迁移，轮换结果只展示一次。
- 在控制台给出迁移风险、剩余数量、轮换入口和错误状态。
- 提供明确的灰度、验证和回退操作手册。

### 非目标

- 不批量导出、恢复或持久化 API Key/Signing Secret 明文。
- 不新增绕过权限的批量轮换接口。
- 不把历史密钥转换成可推导的签名密钥。
- 不在本阶段改变默认的强制配置；生产切换仍由部署配置和启动前检查共同控制。

## 数据与状态定义

迁移状态只统计“活跃 Agent + 活跃凭证”：

- `migrated_agents`：存在活跃凭证，且 `signing_secret_ciphertext` 非空。
- `legacy_agents`：存在活跃凭证，且 `signing_secret_ciphertext` 为空。
- `total_agents`：上述两类之和。

撤销凭证不参与迁移统计。查询只返回 Agent 的 ID、名称、环境、状态和最近使用时间，不返回 key hash、加密密文或任何秘密字段。

## API 设计

### `GET /api/v1/agents/migration-status`

要求当前 Session 具备 `agent:read` 权限。参数：

- `page`，默认 1，最大 100；
- `page_size`，默认 20，最大 100；
- `q`，可选，按 Agent ID 或名称搜索。

返回摘要、历史 Agent 列表和分页信息。服务端强制使用当前 Session 的 `tenant_id`，禁止客户端指定租户。

### 启动前检查

当 `AGENT_SIGNATURE_REQUIRED=true` 时，API 启动流程在监听端口前查询全局活跃历史 Agent 数量。查询失败或数量大于零都阻止启动，并输出不含秘密的可操作错误。兼容模式下不阻止启动，但迁移状态 API 和控制台仍可用于推进迁移。

## 事务与安全

凭证迁移沿用既有单 Agent 轮换事务：撤销旧活跃凭证、创建加密签名密钥凭证、写入审计记录必须在同一数据库事务中成功；失败则整体回滚。新凭证只在轮换响应中返回一次，前端只在内存中短暂保存。

启动预检是只读检查，不修改数据。回退只允许把配置切回兼容模式并重新部署，不能恢复已撤销的历史凭证。

## 可观测性与验收

- 迁移状态 API 可按租户查看剩余历史 Agent，并可搜索。
- 强制模式启动日志明确报告预检失败原因和数量。
- 轮换已有审计记录；轮换失败不可静默忽略。
- 验证包括 Go 单元测试、前端测试与构建、MySQL/Redis 真环境集成测试，以及强制模式下的启动预检测试。
